# 设计文档：`srelay ui` 本地记忆仪表盘

> 版本 v1.0 · 状态：草案（待评审）
> 定位一句话：**给记忆开的观察窗，不是给产品开的第二前端。**
> 前置依赖：PR #3 第一批（watch 架构强化）合并后开工——仪表盘展示的守护状态语义随该批变化。

---

## 1. 背景与目标

### 1.1 要解决的问题

- **记忆不可见**：用户对自己"哪里有记忆、量多大"的感知为零，只能靠 CLI 逐项目敲 `status`/`list`。透明是本产品的立身卖点，但当前只有文本一种呈现。
- **多项目运维痛点已被外部用户撞上**（Issue #2 / PR #3 的 `--global` 批次）：全局守护下各项目状态分散、`watch --status` 尾巴冻结，跨项目巡检只能硬啃命令行。
- **价值感知延迟**（方针评审遗留问题）：20-50 个会话之后用户才"啊哈"。可视化是把这条曲线压短的最便宜手段。
- **传播弹药**：README / Show HN 一张仪表盘截图的说服力远超 ASCII 原型图。

### 1.2 成功判据（可验收）

1. `srelay ui` 一条命令，3 秒内浏览器呈现全部注册项目的记忆概貌（项目数、会话数、磁盘占用、守护存活）。
2. 从总览到"某个项目最近 30 天每天涨多少消息"不超过 2 次点击。
3. 全程**零网络外呼、零新增依赖、零写操作**——npm 包体积增长 < 80KB。
4. 非本人进程访问一律被拒（见 §5 安全模型，有测试矩阵背书）。

### 1.3 非目标（v1 明确不做）

- ❌ 任意写操作——**v1.4 修订（U14）**：开放唯一写口「会话遗忘」，走与 CLI `srelay forget` 同一核心（`core/forget`：事务删除 + 墓碑 + ignore 规则 + 审计），触发者标记 `ui:forget`；其余写操作（标注/模式切换/编辑）仍禁
- ❌ 消息级删除：会话是不可变的捕获记录，删除中间单条会破坏 seq 完整性与决策/摘要引用；"这条别被记住"的正确粒度是会话级遗忘（产品遗忘权语义）
- ❌ 远程访问 / 局域网访问 / 账号体系 / HTTPS
- ❌ 前端框架、构建链、图表库、CSS 框架
- ❌ 实时推送（WebSocket/SSE）——v1 用轮询/手动刷新
- ❌ 替代 `srelay status`（CLI 面板保留，两者共用同一批查询函数）

## 4. 技术架构

### 4.1 第三个薄呈现层（六边形架构的教科书用法）

```
                    ┌─────────────┐
                    │ SearchService│  ← 核心域（零 IO 纯逻辑，不动一行）
                    └──────┬──────┘
           ┌───────────────┼────────────────┐
      ┌────┴────┐    ┌─────┴─────┐   ┌──────┴──────┐
      │  CLI    │    │ MCP Server│   │  UI Server  │  ← 新增（node:http）
      └─────────┘    └───────────┘   └──────┬──────┘
                                            │ 只读
                              ┌─────────────┼──────────────┐
                        SQLite(readonly)  registry     pipe/lock 探测
```

- **HTTP 层**：`node:http`，无框架。路由表 6 条 GET，全部 JSON。
- **前端**：单 HTML 文件（含 CSS/JS/SVG），**以 TS 模板字符串内联在 `src/ui/public.ts`**，由 tsup 一并打包进 dist。理由：`files` 清单零改动、`check:artifacts` 零风险、npm pack 后无路径解析问题（本仓库踩过产物缺文件的坑）。
- **图表**：手写 SVG 柱状/条形图（~100 行 JS），不用图表库。

### 4.2 目录与文件

```
src/ui/
  server.ts    # http.createServer、路由、token/Host 校验、生命周期（前台）
  api.ts       # 数据装配：registry 白名单、聚合查询、TTL 缓存
  public.ts    # export const HTML = `<!doctype html>…`（整个前端）
test/ui/
  api.spec.ts        # 数据装配单测（内存库 + 临时 registry）
  server.spec.ts     # 集成：起真端口，fetch 断言 + 安全矩阵
```

`bin/srelay.ts` 注册：`.command('ui').description('本地记忆仪表盘（只读，127.0.0.1，默认随机端口）')`，选项 `--port <n>`（固定端口，bookmark 用）、`--no-open`（不自动开浏览器）。

### 4.3 API 设计（全部 GET，JSON 信封与 CLI --json 同构）

| 路由 | 参数 | 返回要点 | 数据来源（全部现有函数） |
|------|------|----------|--------------------------|
| `GET /api/overview` | — | 全部项目卡片 + 汇总 | `registryCandidates()` × `countsByState/countsBySource` × `fs.stat(relay.sqlite)` × `config.json` 模式 |
| `GET /api/project` | `root` | 状态条 + 构成 + 决策 + 未决 | `loadConfig` + `countsBy*` + `listDecisions`（注意：依赖 PR#3 批一的"取最新 N"修复）+ `listUnresolved` + `recentScopeLogs` |
| `GET /api/project/sessions` | `root,state,source,q,page` | 分页会话列表 | `listSessions`；`q` 走 `SearchService`（FTS，懒加载 jieba） |
| `GET /api/project/growth` | `root,days=30` | `[{date, msgs}]` | `SELECT date(created_at), count(*) FROM messages GROUP BY 1`（新查询，加进 `store/db.ts` 导出） |
| `GET /api/health` | — | `{ok, version, uptime}` | 进程内 |

**铁律：`root` 参数必须命中注册表白名单**（`registryCandidates()` 的 root 集合），杜绝任意路径读取。磁盘大小只 stat 注册表内的固定文件（relay.sqlite、watch.log、FTS 同库不分算）。

### 4.4 缓存与开销

- 每项目聚合计 `Map<root, {snap, at}>`，TTL 3s；增长曲线 TTL 30s。注册表规模典型 < 20 项目，聚合查询毫秒级，冷打开 N 个只读连接在首次请求时惰性建、进程内复用（`readonly: true` + `busy_timeout`，与守护 WAL 并发安全——同一套并发假设，PR#3 已确认全库连接带 busy_timeout）。
- 前端刷新节流：手动刷新按钮 + 总览 10s 自动轮询（仅 `/api/overview`），详情页不自动轮询。

### 4.5 性能预算（对齐技术方案 §九的预算文化）

| 指标 | 预算 | 手段 |
|------|------|------|
| `srelay ui` 到端口就绪 | < 300ms | 不初始化 jieba（懒加载），只读注册表 |
| 首屏渲染 | < 100ms | 单 HTML 无构建、无外部资源、内联样式 |
| `/api/overview` p95 | < 80ms（20 项目） | 聚合缓存 + 惰性连接 |
| 常驻内存 | < 60MB | 无框架；HTML 一次加载 |

## 5. 安全模型（零外呼红线的第一次开口，必须最严）

1. **默认关闭**：不启动任何服务器，除非用户显式执行 `srelay ui`。
2. **只绑 127.0.0.1**：`server.listen(port, '127.0.0.1')`，永不绑 0.0.0.0 / ::。
3. **一次性 token**：启动时 `crypto.randomBytes(16)` 生成，打印 `http://127.0.0.1:{port}/?token={t}` 并自动开浏览器（`--no-open` 可关）。页面首次加载读 query 后 `location.replace` 去掉 token（不留在前进/后退历史），存 `sessionStorage`，后续 API 调用以 `X-Srelay-Token` 头携带。
4. **双重校验，各司其职（v1 实测修订，U13）**：
   - `Host` 头必须是 `127.0.0.1:{port}` 或 `localhost:{port}`，**对所有请求**（含 HTML 外壳）—— 防 DNS rebinding（外域解析到 127.0.0.1 后同源读取的经典攻击）；
   - token（`X-Srelay-Token` 头）只强制于 **`/api/*` 数据面** —— 防本机其他进程/其他浏览器页盲扫；
   - **HTML 外壳免令牌**：外壳不含任何数据（数据全靠令牌保护的 API 拉取），刷新/收藏/裸地址打开都能拿到页面，由前端按 sessionStorage 令牌决定渲染仪表盘还是引导页。初版曾对外壳也要求令牌——而页面为防历史泄露会抹掉 `?token=`，两条规则打架导致刷新必死，实测翻车后放开。
   - **永不返回 CORS 头**：即使 token 泄露，跨源 JS 也读不到响应（浏览器拦截无 CORS 的读）。
5. **只读到底**：DB 以 `readonly: true` 打开（`store/db.ts` 新增 `openReadonly()`）；HTTP 层无任何非 GET 路由——405 兜底。
6. **前台生命周期**：Ctrl-C 即停，不做守护、不做后台驻留——本仓库刚花了一个整批 PR 根治孤儿守护（Issue #2），仪表盘不新增这一类风险面。
7. **默认随机端口**；`--port` 固定端口属用户自担便利性选择（token 仍强制）。

### 5.1 安全测试矩阵（`server.spec.ts` 必须全绿）

| 攻击面 | 用例 | 期望 |
|--------|------|------|
| 无 token | `fetch('/api/overview')` | 403（HTML 外壳 `/` 免令牌，见 U13） |
| 错 token | 错误 `X-Srelay-Token` | 403 |
| DNS rebinding | `Host: evil.com` | 403 |
| 跨源读取 | 响应头断言 | 无 `Access-Control-Allow-Origin` |
| 任意路径 | `root=D:\无关目录`（不在注册表） | 404 `project not registered` |
| 写请求 | `POST /api/anything` | 405 |
| 只读破坏性尝试 | 对 readonly 连接执行写 | SQLite `READONLY` 错误，库无变化 |
| 非本机绑定 | netstat 断言 | 仅 127.0.0.1 监听 |

## 6. 测试策略

- **单元（api.spec.ts）**：内存库 + `SRELAY_REGISTRY_DIR` 重定向（沿用 registry 的测试惯例，不污染真实家目录）；overview 聚合正确性、growth 查询边界（空库、单日、跨时区日期截断用 UTC date()）、TTL 缓存命中。
- **集成（server.spec.ts）**：真端口起服，fetch 全 API 正反例 + §5.1 矩阵。
- **手动验收**：Windows/macOS/Linux 各跑一次首屏截图；`--port` 固定端口复用；守护运行中（WAL 并发）打开仪表盘不阻塞守护写入。

## 8. 决策日志

| # | 决策 | 理由 / 被否方案 |
|---|------|----------------|
| U1 | 只读，v1 零写接口 | 写路径进网页会复制三入口逻辑或迫使门面改造，复杂度不匹配收益；"看"先立住 |
| U2 | 零新增 runtime 依赖，前端无框架无图表库 | 包轻是既有优点；tsup 内联模板字符串使 `files` 清单零改动（否决：静态资源目录——有产物缺文件风险） |
| U3 | 默认随机端口 + 一次性 token + 自动开浏览器 | 固定默认端口会被本机任意进程扫描；随机端口是 Electron 同款安全姿态 |
| U4 | Host 头校验 + 永不 CORS | 双保险对抗 DNS rebinding 与跨源读取 |
| U5 | 前台运行，无守护形态 | 不制造新的孤儿进程风险面（Issue #2 刚根治） |
| U6 | root 白名单 = 注册表 | 防任意目录读取；注册表本来就是"这台机器有哪些记忆"的权威答案 |
| U7 | HTML 内联于 TS 而非独立文件 | 规避 `check:artifacts`/npm pack 的资源遗漏整类问题 |
| U8 | 中文 UI、与 CLI 同词表 | 产品主语言一致性；i18n 留 v1.x |
| U9 | 依赖 PR#3 批一先行合入 | 守护状态语义（全局守护/管道锁/decisions 最新序）随批一变化，先合再做免返工 |
| U10 | 总览 10s 轮询、详情手动刷新 | v1 不引推送复杂度；本地只读轮询成本可忽略 |
| U11 | `status` CLI 保留不动 | 两者共用底层查询函数，无维护双份逻辑问题 |
| U12 | 增长曲线按 UTC date() 聚合 | 与库存 `created_at`（ISO/UTC）口径一致；前端标注时区 |
| U13 | HTML 外壳免令牌，token 只锁 /api/*（v1 实测修订） | 外壳零数据无秘密可泄；初版锁外壳与"页面抹 ?token= 防历史泄露"互斥，刷新必死。放开后刷新/收藏可用，安全面不变（Host 校验仍覆盖一切请求） |
| U14 | 写域开放：仅「会话遗忘」一条，复用 core/forget 核心（v1.4，产品主人决策推翻 U1 原版） | 删除若自己写 SQL 会被守护重摄（源文件还在）——必须走 forget 墓碑双闸；CLI 与 UI 同一代码路径，审计记 ui:forget；消息级删除否决（粒度错误，破坏会话完整性）；POST 需 X-Srelay-Token 头，自定义头跨源发不出（无 CORS 响应）→ CSRF 天然免疫 |

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 范围蠕变（"顺手加个编辑"） | 高 | §1.3 非目标清单 + U1 是评审级红线，越界须另立文档 |
| 安全叙事被误解为"产品开始联网" | 中 | README/CHANGELOG 措辞预案（§7 末段）；默认关闭 + 仅回环 + 只读三重强调 |
| 大库（数百 MB）增长查询慢 | 低 | GROUP BY 走 created_at 索引；30s 缓存；极端库可加 days 参数上限 |
| token 泄露到浏览器历史 | 低 | location.replace 清理 + sessionStorage；本地单用户威胁模型下可接受 |
| 与 fork（rui08984-dot）功能撞车 | 中 | 他的 fork 已有 ui 方向演进的自由；本设计以主线节奏推进，合入其修复批后再做，避免重复实现其已修的底层 |

# 地图纪律（SessionRelay 本土化版）

> **上游出处**：本技能是 mellos-mapping 技能原文（v0.28.0）的**本土化**——纪律保留，**MCP 与面板全部替换成 `srelay map` CLI**。
> 归属与 MIT 原文见 `src/map/NOTICE-mellos.md`；接口契约见 `docs/design/design-map-layer.md`；命令与字段速查见 `docs/map-cli.md`。
> **本仓库没有 `mmap_*` 工具，也不要去找**：全部动作都是 `srelay map …` 或它的库接口。

一句话：**地图是账本，不是法官。** 工具只拒绝**结构损坏**（层带 rank、边只能严格向下所以天生无环、id 唯一、状态闭合词表、未知字段拒绝）；
**什么时候声明、什么时候开工、什么时候算完成——那是你的纪律，写在这一页里。**
如实报告：一张不好看的地图正在正常履职；一张粉过的地图是这系统唯一活不下来的故障模式。

## 0. 两个前置事实（先知道，免得白找）

1. **地图的观众是看板**：`<root>/.sessionrelay/map/<page>.json` 由守护的既有 sync 路径自动投影到 `progress.md`（模块列 = `auto:map` 的行）与 `board.mmd`（层带 subgraph + 真边）。
   **你不需要"把地图放到屏幕上"**（上游那套 `mmap_open` 面板在这里不存在）：**写进地图 = 自动进看板**，下次会话的开场简报自然带着它。
   投影只发生在展示层：**看板上的红/绿不会改地图里的 status**。
2. **`srelay map` 不是每轮都要跑的东西**：它是**里程碑**动作——开工声明、状态切换、证据落账、收尾对账。日常代码改动的留痕是 relay 采集与看板的活，别拿地图当日志。

## 1. 什么时候开地图

没有 MCP，也就没有 `mmap_setup` 的持久策略；本仓库的规矩是**对话式约定**：

- **默认判据（≈上游 `complex`）**：多个互相作用的模块、新子系统、分层重构、**大约一小时以上的活** → 开地图。
- **小改动、单行修复、纯问答** → 不开。**一张只有一个节点的地图是噪声。**
- **拿不准就问用户一句**，别自己替他决定。
- **两条永远压过默认判据**：① **用户明确要一张地图 → 任何情况下都开**；② **地图一旦开了，就必须持续如实更新**，不管这活后来变得多小。

已经开工一半才发现该有地图？**停下来先补声明**，状态照实写：**写完没验证的写 `doing`，不是 `done`**。

## 2. 工作循环

### ① 先恢复，再补缺（Resume first, then fill gaps）

**新会话 / 压缩之后不是新努力。** 开场先看盘上有什么：

```bash
srelay map read --resource pages            # 有哪些页、各页节点/边数、revision
srelay map read --resource map --json       # 当前页全貌（层/组/泳道/节点/边/context）
srelay map read --resource nodes --status doing   # 现在真正在跑的是谁
```

**绝不靠"探默认文件在不在"来判断有没有地图**——所有工作都在命名页上时，默认页可能压根不存在。
有关键字查询就 `srelay search` 先找回上下文；**用 read 返回的 id，不要用显示用的 label**（label 是可以改的，id 是边的锚）。

### ② 只声明缺失的结构（Declare only what's missing）

补 `declare` 之前先跟盘上的图对一遍：**已经存在的 id 不要再声明一次**（重复 id 会被拒，且把"新设计"和"旧事实"搅在一起）。
新努力就把它的**意图设计**一次性声明出来：title、层带（rank 0 = 最底层）、每个计划中的节点、以及边。**全部以 `todo` 起步**——这是一份可以被否决的"幽灵设计"，代码还不存在时它就该长得像"打算做成什么样"。

### ③ 自底向上点亮（Work bottom-up）

实现之前先把节点切到 `doing`，并**优先做完它下方的依赖**。
同层互不依赖的兄弟节点**不需要人为排队**：一起开工（几个 `doing` 并列）是**如实报告**，不是违纪。
如果你故意在未完成的下层之上动工，**在对话里说清为什么**。

### ④ `done` 必须有证据（No evidence, no done）

只有**验证真的过了**才写 `done`，并把"过的是什么"写进 `evidence`（例：`vitest: 23 passed`、`npm run typecheck 通过`）。
**没证据就没有 done。** 看板投影对"无 evidence 的 done"会挂上"无证据"三个字——那是给你的提醒，不是装饰。

### ⑤ 回归向上蔓延（Regression spreads upward）

后续工作弄坏了某个 `done` 节点：**先**把它切成 `regressed`（坏在哪写进 `evidence`），**再**动手修。
然后**逐个走一遍所有（直接或传递）使用它的节点**：它们的 `done` 是在一个已经不再成立的地基上验过的，**默认一并 `regressed`**；
想让它保持绿，必须给出理由（它自己的验证又跑绿了，或者它根本不碰坏掉的那部分行为）。
修好之后，**每个节点各自由它自己的验证重新通过**才恢复。

### ⑥ 诚实修订幽灵（Revise the ghost honestly）

设计是假设，声明过的东西**都可以改**。节点裂开了、多了个新的原语、层带分错了——**改计划的那一轮就把地图改掉**：
`update` 能把节点挪到别的层（`layer`），也能改层带的名字与 rank；`remove` 清掉清空了的边、节点、分组、泳道与层带。
**清可选字段写 `null`**（**必填字段给 `null` 会被拒**）；空串本身合法，但"清空"一律用 `null`，语义才清楚。
**地图跟你脑子里的意图不一致，就是这系统唯一活不下来的故障模式。**

### ⑦ 保持 `context.next` 最新（那是接力棒）

`context.summary` 一句话说清"这张图是什么"；`context.next` 是**给下一个会话的第一件事**——它会**排在看板最上面一行**。
每完成一个里程碑就刷一次，别让接手者读一份过期的一步。

### ⑧ 收尾清理（Clean up a finished effort）

页会堆积，原则是**一个努力 = 一张页**。努力结束、地图已履职，别急着收摊——**先看它还有没有人读**。

**没有「删页」动词**（契约 §4.2，与"绝不覆盖人写内容"同一条纪律）：**页的建立**由 `apply` 的 `declare` 完成（`title` 缺省 = 页 id），**页的删除是用户手动删文件**（`.sessionrelay/map/<page>.json`）——**工具不会替你删**。你能做的是：用 `remove` 把临时节点／空壳边清干净、把 `context.next` 写成"这张页已完成、可以退场"，然后把删不删**交给用户**。**绝不动一张可能还有人正在读的页。**
**只在用户点头时做，绝不自作主张**；**绝不动一张可能还有人正在读的页**。

## 3. 建模指引（上游原文的本地化版）

- **节点 = 可构建、可验证的工作单元**（一个模块、一份契约、一个渲染器），**不是**"写测试"这种任务，**也不是**文件。
- **一个层带挤到大约五个以上节点就声明分组**（`group`）：分组是该层带里的一个**真子集**——装下整个层带只是给它改了个名，没有意义。组的状态由成员**推导**，**永远不要自己编**。
- **每个节点都带 `detail`**：一到三句说清职责、契约、关键决定。设计变了就更新——**过期的 detail 是地图上的一句小谎**。
- **状态往顶层推**：下层取值、出值；可变状态集中在最顶上的编排者手里，显式持有并作为参数往下传。下层节点的 `detail` 里出现"它记得上次调用"这种话，就是设计在发臭——**先重构，再往上盖**。
- **层只编码依赖方向**，别的什么都不编码。如果 A 需要同层的 B：要么 B 其实更低层，要么 A 和 B 本是同一个节点——**改结构，别硬连一条边**。
- **边的意思是"使用"**：上层节点**真的**调用、组合或读取了下层节点。**不画愿望边。**
- **id 是稳定的 kebab-case slug**；label 是短显示名（中文可以），改名不会断边。
- **一个努力 = 一张页**：真正独立的努力（并行会话、不相干的子系统）**另开一张页**（`--page`），别混页、别覆盖一张已经完工的图。
- **上游的 submap / 渲染种类（architecture・dataflow・behavior-tree・sequence）本仓库未移植**：需要"深入一层"时，另开一张页并在 `context`（或节点 `detail`）里写明它从哪张页分出去的。**状态机不在地图的能力范围**：状态转移会成环，而这里的边只能向下——**如实说做不到，别硬塞**。

## 4. 绝不手改地图文件

地图是 JSON 文件，但 **`edit` / `write` 直接改它是违纪**。原因都是实现里真的会发生的事：

- 严格读：**类型不对、未知字段一律拒绝**（写回会毁掉手改过的文件）；
- 每次写都要过 **`expectedRevision`**（revision = 规范化内容的 sha256）：手改会让所有人在下一次写时吃 `CONFLICT`；
- `temp + rename` 的原子保存与单文件锁是为了并发安全——**绕过它 = 制造别人看不见的丢写**。

**所有写入走 `srelay map apply`（或 `declare`/`update`/`remove` 三个糖）**；一处改不动的时候，先 `read` 拿最新 revision 再重试。

## 5. 与看板的接口（一句话备忘）

| 地图 status | 看板上长什么样 |
|---|---|
| `todo` | ⬜ 待办 |
| `doing` | 🔄 进行中（有 evidence 就附上） |
| `blocked` | ⛔ 阻塞 |
| `done` | ✅ 完成（**没 evidence 会附"无证据"**） |
| `regressed` | ⛔ 回归（"已做过又坏了"） |
| `done` 但某个 `sources[].sha256` 对不上 | ⛔ 待复验（"⚠ 源码已变：<文件名>"） |

看板里的 `auto:map` 行**每次由守护重写**，人写的行逐字不动。所以：**想让下一场会话看见什么，就写进地图的 `context.next` 与节点状态**，别去手改 progress.md。
完整对照表（含行序、上限、去重规则）见 `docs/map-cli.md`「状态词表与看板投影」。

## 6. 随时自查（Standing state）

任何时刻，地图对上它自己的看板投影都应能一眼回答：**设计了什么／什么已经建成并验证／现在真正在跑什么／有没有地基裂了**。
**如果一眼会误导**（有 `doing` 没在跑、有 `done` 没证据、源码变了状态没跟上），**先把地图修好**，再干别的。

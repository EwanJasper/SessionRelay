# 交接与全资源地图（Handoff-Atlas v1.0）

> **v2.1（2026-10-16）**：触发方式**改回正常（该用就用）**，把「别每轮都写交接」做成**正文里的规矩**，而不是靠收窄触发条件。
> 起因（用户实测反馈）：改成「只在显式点名时使用」之后，**该出手的时候它反而不出手了**；
> 而原来的自动触发，用户也**从没见它主动跳出来过**——说明收窄描述并没有省下什么，只是削弱了能力。
> 所以真实纪律应该是：**触发可以自动，但产出要有门槛**——见下一节。
>
> **v2.0（2026-10-16）**：**state-stack** 并入（成为 §7）。
> v1.0（10-15）：**handoff v2.3** + **project-atlas v1** 合并（用户令：「两个技能融合成一个，再结合框架」）。
> 合并理由：三者**本来就是同一条流水线的三段**——状态栈是「底座怎么跑」，交接件是「交给人看什么」，地图是「项目有什么」。
> 分开维护的实测代价：handoff 的 B5-2 只是「指向 project-atlas」，常只刷文件全图、忘写现状节；而 state-stack 的看板填表纪律又与交接侧的看板同步各写一遍。

### 什么时候才写（这条比触发方式重要）

| 情形 | 写不写交接件 |
|---|---|
| 用户明确说「写交接 / 换会话继续 / 交接一下」 | ✅ **写**（这是本技能的主用途） |
| 收尾时发现**有棒要交给别人续**、或**上下文快满了要换会话** | ✅ 写 |
| 用户只是问了个问题、改了个小东西 | ❌ **不写**——证据式收尾（说清楚改了什么 + 给路径）就够 |
| 每轮对话结束 | ❌ **绝不写**：这是上下文浪费的主要来源 |

**判据一句话**：**「下一个人（或下一条命）不读这份文档就会走弯路」才写**；
只是「记录一下我做了啥」——那是 relay 自动采集与 progress.md 看板的活，不是交接件的活。

## 两条核心规则（原文各一条，这里并列——它们是同一条纪律的两面）

```
1) 只引用不复制  ——  已在别的产物里的内容给路径，绝不复述
2) 每行都要有路径 + 一句「是什么」  ——  只列路径不说是啥 = 让接手者再问一遍
```

**违反这两条的字面，就是违反它们的精神。**

## 0. 先看这张图：四层记忆，各写各的，别互相抄

| 层 | 载体 | 谁写 | 粒度 | 读者的用法 |
|---|---|---|---|---|
| **L1 自动日志** | SessionRelay 的 relay 库（`srelay`） | 守护自动采集 | 原始消息级 | 检索（`srelay search`）／回跳原文 |
| **L2 模块状态** | `progress.md` 看板 ＋ `architecture.mmd` 依赖图 | 施工时随手改 | 模块/任务行 | **进开场简报**（模型一眼看到在跑什么） |
| **L3 断点锚** | `<棒名>-PROGRESS.md` | 施工期（见 **progress-anchor** 技能） | 棒/回合 | 换棒续跑的唯一可信状态 |
| **L4 提炼入口** | **① 交接件**（唯一入口）**② 全资源地图** | 收尾时（本技能） | 项目级 | 零上下文接手者的第一读 |

**分工铁律**：L1 原文最全、L4 最精炼、L2 机器可读、L3 只对施工者有意义。**同一事实只在一层"详写"，其余层给路径。**

> 没有 SessionRelay 的项目：L1/L2 退化为「git 历史 + 你自己的进度文件」，其余照旧。

### 0.1 同一张图的另一半：谁**自动**送进模型眼前

上表说的是「东西写在哪」，这一节说的是「**东西怎么到模型眼前**」——两条路，别混：

| 通道 | 载体 | 时机 | 谁负责 |
|---|---|---|---|
| **自动注入** | 开场简报（看板🔄⛔行 + 决策 + 🗂 最近在动） | ZCode：SessionStart 一次；DSH：**每个模型步骤前**现查一次 | 框架自身（hook / 插件） |
| **人取** | 交接件、全资源地图、断点锚、relay 检索 | 用户点名或接手者主动读 | 本技能 / srelay search |

**这是「被动触发」能成立的第二个理由**：日常上下文里的「不失忆」由**自动注入**兜底，
本技能只在**需要把知识固化成文**时才被叫起来。两件事分工清楚，才不会为了「状态更准」每轮都写一遍交接。

> ⚠️ **静默半失效**（本框架最嫌恶的故障）：注入通道全绿而用户什么都看不到。
> 自查顺序见 §7；一句话——**装好了 ≠ 注入了**。

## 1. 先选流程（问一句项目规模）

- **A · quick**：短任务收尾、单会话内小交接 → §2
- **B · ledger**：多会话长项目、有在跑的任务棒、换新会话续作 → §3（内含 A 的全部要求）

**地图（§4）两级都要，只是深度不同**：A 级只要「现状快照」一节；B 级要「文件全图 + 现状快照」两节齐全。

**过度使用防护**：小任务收尾**不需要**交接文档，证据式收尾就够；B 全套（B1–B5）只用于真多会话长项目。

**前置提醒**：长项目在**施工期间**就该用 **progress-anchor** 技能落盘锚（微步回合制／收据化／僵尸判死）——交接文档质量 **90% 由施工时的落盘决定**，等交接时才补救就晚了。

## 2. A · quick 交接（短任务）

1. **问清聚焦点**：下一场会话要干什么——用户的传参就是交接文档的定制方向。
2. **写交接文档**，存 `.scratch/handoff/<主题>-<日期>.md`（目录不存在就建；项目有自己的 docs 惯例就随项目）：
   - **当前状态**：做到哪一步、最后验证结果（**本会话实测盘点，非推测**；带证据：文件/输出路径）。
   - **下一步**：接手者的第一件事。
   - **关键上下文**：只放别处查不到的东西——踩过的坑、拍板过的决定、失败过的路。
   - **产物索引**：相关文件全部给路径，不复制内容。
   - **地图指针**：项目有全资源地图就写它的路径（**别把地图内容抄进来**）。
   - **建议技能**：接手者应加载哪些技能（写名字）。
   - **脱敏**：API key、密码、个人隐私绝不入档。
3. **验收**：假想一个零上下文的 agent 只读这份文档能不能接着干？不能就补。

## 3. B · ledger 续作（长项目实战协议）

### B1 · 入口交接模板（唯一入口=最新一份，覆盖此前全部）

```markdown
# <项目> · 交接（<日期> · <为何交接：装不下/主动换班/在跑棒断点> · 新对话续作唯一入口）

> 开场对接手者说：「按 <本文件名> 续作」即可。本文件=唯一入口，覆盖此前全部交接链（历史层按需回溯）。
>
> **交接链全清单（必写，紧随开场行）**：逐份列出全部历史交接文件名＋日期＋角色（表格，只引用不复制；
> 权威全量文档若不在本目录，注明实际路径）。凭记忆写"覆盖此前全部"不算数——**以盘上目录实测枚举为准**，
> 漏一份=未完成交接。**用 §5 的 anchor_audit.mjs --chain 生成，不要手抄。**

## 0. 一分钟了解现状（**本会话实测盘点，非推测**）
## 1. 在跑的棒（表：线 | 断点锚 | 续作方式）——旧棒断=不唤醒，从锚换新棒
## 2. 已收口勿重做（全部 git 可查，给 commit 链；含负结果与失败过的路，防重蹈）
## 3. 铁律与纪律（违反=弃棒）
## 4. 拍板记录（用户已定方向，勿重新发散；可选）
## 5. 待用户事项（等拍板项编号列出）
## 6. 环境备忘（高频坑速查）
## 7. 产物索引（规格/证据/数据分组给路径，只引用不复制；可选）
## 8. 脱敏确认（本文件与引用产物零 key；涉密项目必写）
```

各棒的进度锚（L3）由 **progress-anchor** 纪律在施工中维护，交接时**只核对并引用其最新状态**。
模板节按项目取舍；**0/1/2/3 与开场后的「交接链全清单」为必写**。

**范例**：B1 模板本身即范本；下笔前可对照你项目里已有的交接文档找手感（只引用路径，不复制内容）。

### B2 · 判据冻结（实验/评审类项目可选）

判据写入 PREREG 文件 + hash 钉死；改动=版本递进（PREREG-v2），禁回填旧题。冻结后禁改。
**改冻结件的完整程序** → 加载 **safe-mutation** 技能，读它的 `frozen-artifact` 参考。

### B3 · 勘误文化

交接/进度文档发现错误：**原文零改动**，末尾追加【更正】段（日期 + 正确口径 + 证据链）。
信息失真不可避免，**可追加修正才是纪律**。

### B4 · 零上下文验收 + 锚点审计

1. 按 §2.3 做零上下文验收：假想零上下文 agent 只读入口交接，能否按 §1 的续作方式直接开干？不能就补。
2. 长项目换新会话开场：跑 `node <本技能目录>/scripts/anchor_audit.mjs <入口交接.md> <项目根目录>`
   ——抽查引用的路径/commit/收据是否真实存在。**有红=先处置再开工**。
   报红先分三类再动手（§5 已自动化前两类）：真失效 / 解析口径（通配符、`<占位符>`、嵌套仓库）/ 笔误。

### B5 · 交接前收尾三件（**先做完再写交接**；缺一件=交接未完成）

1. **逐件落盘审计**（把「我印象里做了」变成「盘上可核」）：本阶段每一项声称的产物，逐件核
   ① **存在**（绝对路径 `test -f`/`ls`）② **已入 git**（`git ls-files <path>` 命中，或 `git status` 显示已提交）。
   未跟踪/未提交的当场补。收尾清单**按项目惯例**（示例：**归档四件套**＝收据／变更留痕／索引段／进度锚）逐项打勾；
   任一缺项写进交接的「未落盘」节并说明原因，**不得默认已做**。
2. **索引与地图更新**（**本技能 §4 就是这一步的执行体**）：
   - 项目自身的导航件必须同步到最新：全资源地图**顺序追加一节**（不改旧节；冲突处在新节写明「以本节为准」）；
   - 进度锚（L3）追加本阶段条目；看板（`progress.md`）与依赖图（`architecture.mmd`）按本阶段状态变更同步；
   - 变更留痕追加编号节；
   - 交接文档里**逐条列出**「本节同步了哪些索引」（文件＋节号），接手者可一眼核对。
3. **记忆库同步**（环境有持久记忆时）：把本阶段**非代码可推导**的事实写进记忆（当前状态、拍板、新坑、新命令），并更新记忆索引行；
   交接文档写「记忆已同步／未同步＋原因」。**记忆与交接文档冲突时以盘上产物为准。**

## 4. 全资源地图（Project Atlas）

**用途**：零上下文接手者读一页即可知道「项目有什么、在哪、是什么」。
**不是**：不是目录树 dump（那没有「是什么」），也不是 API 文档。

> 原铁律（并入 §开头规则 2）：**EVERY LINE NEEDS A PATH AND A "WHAT IT IS"**。

### 4.0 ★ 地图有**两类内容**，别混（最易犯的错）

| 类型 | 是什么 | 谁产出 | 何时更新 |
|---|---|---|---|
| **A. 文件全图** | 路径 ＋ 一句话「是什么」（成百上千行） | **本技能生成器** `gen_atlas.py` | 有新文件时，**重跑生成器** |
| **B. 现状快照** | 项目状态（关键指标／各阶段到哪／今天干了啥／卡在哪） | **手写**（追加新节） | **每批活做完** |

**⇒ 「把新做的东西加到地图」＝ 两件事都要做**：

```
新做了一批活
   ├─ A：新文件出现了？  → 重跑 gen_atlas.py --append-section（自动）
   └─ B：项目状态变了？  → 手写追加一节现状快照（生成器不管，靠纪律）
```

**只刷 A ≠ 地图更新了**。实战踩过：文件全图刷到最新，但**现状节还是旧的**
（测试数、账本数、新落地的功能全没体现）⇒ 接手者读到的是**过期的现状**。

**B 类怎么写**：

```markdown
## §N <日期> · **<主题>**（最新；以本节为准；§N-1 为更早快照，冲突处按本节）
<关键指标表：数字 ＋ 证据路径>
<本次落了什么／卡在哪／待拍板>
```

**与 L2 看板的分工**：**模块级状态（✅🔄⛔）由看板 `progress.md` 承载**、依赖图节点着色=状态；
地图现状节给**看板指针**即可，勿复制状态明细（只引用不复制）。地图现状节写的是**看板不承载的那部分**：
项目身份、体量指标、阶段脉络、内容索引。

### 4.1 生成文件全图（一条命令）

> 解释器：本文件用 `python3`；**Windows 上常为 `py`**（本机 `python3` 是商店占位符，不可用）。脚本零第三方依赖。

```bash
py scripts/gen_atlas.py <项目根> [--out <文件>] [--append-section <地图文件>]
                        [--config <json>] [--section-title <标题>] [--check]
```

- 默认输出 stdout；`--out` 写文件；`--append-section` **作为新节追加**到既有地图（**不改旧节**——验证过的纪律）
- **`--check`（v1.1 新增）**：只审不写——把既有地图里引用的路径逐条找回，报「地图里写了、盘上没有了」的**腐烂引用**。
  地图是追加式的，旧节必然会漂；这是**地图腐烂检测**，建议每批活收尾时跑一次。

### 4.2 地图的结构（照这个写）

```markdown
# <项目名> · 全资源地图（<日期>）

> 用途：零上下文接手读本页即可。**唯一入口（交接）**：<交接件路径>
> ⚠ §0 是早期快照，**现状以最后一节为准**（顺序追加，编号越大越新）

## §0 一分钟：项目是什么、现在在哪
<项目身份 + 当前状态表：关键指标 + 各阶段状态 + 在跑什么 + 卡在哪>

## §1..§N 各时段快照（顺序追加，不改旧节）
## §N 最新现状总表（**以本节为准**）
## 文件全图（生成器产出，勿手改）
  ### 根目录（N）
  - path/to/file —— 一句话「是什么」
  ### docs（规格·计划·锚）
  ### .scratch（交接链·研究档案·备份）
  ### src / scripts / test
  ### 其它（目录级）
```

**两条纪律**：① **顺序追加，不改旧节**；冲突处在新节写「以本节为准」。② **每行一句话「是什么」**，不复述内容、不给全文。

### 4.3 一句话摘要怎么抽（生成器已实现）

按优先级：① **人工 override 表**（关键件手写短述，放生成器配置 JSON）② 文件**首个实义行**（跳过 `use strict`／`---`／纯 `#` 行／语言名，取首个 ≥6 字的行）③ 都没抽到 → `（无一句话可抽）`。

### 4.4 折叠与跳过（防地图被淹没）

- 同类目录 **>12 件** ⇒ 折叠成一行 + 代表件 + 指针（如「逐件索引见 `scripts/README.md`」）
- **`.md` 文档类逐件列**（它们正是「是什么」的主体）；`.md` 在 ≤60 件时不折叠
- `.db` 快照体只列**目录级**（体积大且数量极多）
- **跳过**依赖/构建/媒体目录 ＋ **会话/运行产物**（最大噪声源）：
  - 目录名：`node_modules`/`.git`/`dist`/`build`/`venv`/`__pycache__`/`cache`/`coverage`…
  - 目录名模式（比枚举耐新产物）：**`.` 开头的点目录整体跳过**｜`session-*`｜`*_session*`｜`*-profile`｜`playwright`
  - 文件名模式：`*backup*`／`*.min.*` 等（走 `skip_files_regex` 配置）

> ⚠ **默认规则清不干净是正常的**：不同项目噪声源不同（素材库、转写稿、对标视频……）。
> 用 `--config` 的 `sections` **白名单**反而更准——只列你指定的目录。
> 实测：同一项目全量扫 **2627 件**；改 `sections` 白名单后 **103 件**，且全是接手者要看的。

## 5. 脚本

| 脚本 | 用途 | 用法 |
|---|---|---|
| `scripts/anchor_audit.mjs` | 锚点审计：抽查交接/锚里引用的路径与 commit 是否真实存在 | `node scripts/anchor_audit.mjs <入口交接.md> [项目根]`；`--chain` 枚举交接链 |
| `scripts/gen_atlas.py` | 文件全图生成 / 追加 / 腐烂检测 | 见 §4.1 |

**anchor_audit v2（2026-10-15 改，起因：实测 6/53 报红全是口径问题）**：
1. **通配符与占位符不再报红**：`docs/1015-*.md`、`<项目>/.sessionrelay/bench/v<版本>-<时间>.json` 这类**模板写法**改为 ⚪ 提示（附实际匹配数），不当失效；

## 6. 与 SessionRelay（本框架）的集成

环境有 SES 时，本技能的四层记忆可直接落地：

| 步骤 | 命令 / 动作 |
|---|---|
| 施工期自动留痕（L1） | 不用手动——守护按项目采集；**改完代码要提醒"哪个常驻进程需要重启"**（铁律 21） |
| 收尾写记忆（B5-3） | `srelay save --recent 1d --tag <阶段标签>`；跨会话事实/决策也可经 MCP 写 |
| 交接件归档进记忆 | `srelay save <交接件路径>`，接手者可 `srelay search` 找回 |
| 看板同步（L2） | 各项目 `progress.md` + `board.mmd`；守护会自动刷新"自动区"，**人写的行不许被覆盖** |
| 出图 | `srelay kanban graph [--html|--d2]` → `<项目>/.sessionrelay/board/board.mmd` |
| 收尾体检 | `srelay doctor`；项目有守门脚本就跑它（如本框架的 `node tools/check-versions.mjs`，A–H 全绿才算收工） |
| 数字纪律 | **数字必须绑快照与口径**：写 `28/908 @ 22:45 @ 全库口径`，否则数据在动、无法复核（铁律 22） |
| 交接件放哪 | 项目已在 `docs/` 有交接链时**跟随项目惯例**，别另起 `.scratch/handoff/`（同一项目两个交接目录＝接手者必漏一半） |

**与 progress-anchor 的接口**：L3 锚由它维护；本技能在 B5-2 核对锚的最新状态并引用，**不复制锚内容**。
**与 safe-mutation 的接口**：交接里记「改了生产库 N 行」时，那条收据要含 safe-mutation 的五件
（快照路径＋sha／副本演练结果／行数变化／零翻转 diff／偏差披露）。

## 7. 状态栈：怎么用、怎么修（原 state-stack 技能）

> 这一节回答「**这东西平时怎么跑、坏了怎么看**」。§0 讲的是它由哪几层组成，这里讲它的行为契约。

### 7.1 自动注入的三层判定（hook / 插件自动执行，理解它再行动）

| 情形 | 行为 |
|---|---|
| 目录里有 `.sessionrelay/` | **自动注入该项目简报**（看板 🔄⛔ 行 + 决策 + 🗂 最近在动） |
| 无栈，但有历史状态信号 | 注入**「可接入」提示**——信号 = `.scratch/handoff/*.md` 交接链，**或** `.scratch/` 直属的 `*PROGRESS*.md` 锚 |
| 都没有 | **静默**（这是设计：小活零打扰，**不是故障**） |

### 7.2 用户口令 → 你该做什么

| 用户说 | 你做 |
|---|---|
| 「继续」 | 按已注入的简报 + 读全量 `progress.md` 续作；引用状态时**说清"截至看板哪一行"** |
| 「看板」 | 渲染 `progress.md` 表格 + `architecture.mmd` 依赖图 |
| 「接入」 | `srelay init --yes` → 从交接链/锚点提炼模块生成 `progress.md` + `architecture.mmd` → 出面板 |
| 「给 XX 项目开工」 | 同上流程建全套；模块划分来自与用户的方案讨论（讨论结论**直接固化成看板行**） |
| 「刷新面板」 | 重跑面板生成脚本 |
| 「这活派给 pi」 | 出方案拆任务写进看板 → `pi --mode rpc`（headless JSONL）或请用户开 pi 说「继续」 |
| 「状态栈出问题」 | 按 §7.5 排查表逐条诊断 |

**派活最小配方**（spawn 后 stdin 发一行，等 JSONL 事件流回）：

```bash
pi --mode rpc --model <provider/id> <<< '{"id":"1","type":"prompt","message":"读 progress.md 接续：<任务描述>。完成后更新看板行。"}'
```

> **注入 ≠ 强制续作**：简报只是知会现状，**用户下一句话才是指令**。新文件夹静默 = 设计。

### 7.3 看板填表纪律（`progress.md`）

- 四列：**模块 | 状态 | 依赖 | 现状与出处**；
- 状态列必须以 ✅ 完成 / 🔄 进行中 / ⛔ 阻塞或否决 / ⬜ 待办 **之一开头**；
- **格内禁裸竖线**（会把表格切碎）；
- 改动前**先重读最新版**（双工具并发写防丢）。

**并发写铁律**：同一块看板的整理/重生成**归一个会话管**——两个活跃会话互相覆盖时，
「改前重读」也防不住（真实事故：两个会话同时重建看板，一侧整段丢失）。
**改前重读是底线，不是保险。**

**自动区**：看板可以有机器维护的「自动区」（如 ZCode 真待办），
但**人写的行一个字节都不许被覆盖**——清理时必须只动自动区。

### 7.4 运行态与排障（按需读）

**守护缺陷、门卫脚本、排障表、单一事实源**这四块是**参考材料**，已拆到 `references/state-stack-ops.md` ——
只有在**守护不工作 / 简报没弹 / 看板不对 / 要改注入脚本**时才去读。

一句话先记住：**常驻进程不会因为文件更新而更新**——「文件更新了但行为没变」九成是没重启；
而「装好了却什么都没注入」是静默半失效，按那份参考逐条查。

## 9. 常见托词（合并两侧，**都是真发生过的**）

| 托词 | 现实 |
|---|---|
| 「内容不多，干脆抄进交接文档吧」 | **只引用不复制**——同一条信息两处存，必然漂移；改一处忘一处，接手者读到的是旧的那份。 |
| 「凭记忆写'覆盖此前全部'就行」 | 实测漏列过 **12 份**历史交接，用户核出才补齐。**以盘上枚举为准**。 |
| 「文件太多，全列上吧」 | 实测全量扫 **2627 件**（含会话日志/素材/转写稿）⇒ 等于没列。**白名单才准**。 |
| 「地图旧了，直接改那一节」 | 改了旧节 = 丢了「当时是什么」。**追加新节**，冲突处标「以本节为准」。 |
| 「只刷新文件全图就算更新地图了」 | 地图会**看起来新、读起来旧**（现状节没动）。§4.0 两件事都要做。 |
| 「摘要让模型现写就行」 | 每次重写 = 不可复现 + 烧 token。**生成器抽取＋关键件 override**，重跑结果稳定。 |
| 「锚点审计报红，算了先开工」 | 红=证据缺失或笔误。**先处置再开工**；但先分三类（真失效/口径/笔误），别把模板写法当失效。 |
| 「小改动也要写全套吗」 | 反了：小任务**别**套 ledger 全套，证据式收尾就够。 |

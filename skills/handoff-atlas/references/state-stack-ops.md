### 7.4 守护进程：已知缺陷与门卫

- **上游资源缺陷（实测）**：watch 守护不绑父生命周期（调用方退出 → node 成孤儿，实测同时 18 个实例）、
  无有效单实例锁、句柄/内存泄漏（长跑单实例几小时烧掉一小时 CPU）。
- **门卫脚本**是唯一正确的启停方式：清光旧实例 → 按注册链路拉起**一个** → 验证实例数 = 1。
  仓库里对应 `tools/` 下与安装器同级的门卫脚本（本机是 `scripts/watch-guard.ps1`）。
- ⛔ **禁止无超时 spawn** `watch --foreground`；测试用 `--status` 或带超时。
- `watch --status` **按项目锁判断，跨项目查询会误报「未运行」**——信门卫输出或守护日志心跳。

### 7.5 排障表

| 症状 | 先查 |
|---|---|
| 简报没弹 | ①目录里有没有 `.sessionrelay/`（新文件夹静默是设计）②守护在不在跑（门卫输出）③手跑一次注入脚本看输出 |
| 简报是旧内容 | **常驻进程没重启**：文件更新 ≠ 进程更新（ZCode 新开会话 / DSH 重启） |
| 看板不对 / 面板旧 | 看板是不是被并发写覆盖过；面板脚本重跑一次 |
| 守护没跑 / 多实例 | 上门卫脚本；别手动 spawn |
| 记忆库采不到会话 | 采集源配置里有没有你那个端；库里 sessions 数是否在涨 |

**改任何注入脚本后必跑回归**（三目录 × 敌意样张 × MCP 握手），全绿才算改完。

### 7.6 单一事实源
